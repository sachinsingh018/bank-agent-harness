# UI facts (2026-11-19)

Facts for the UI work, read from the repo and the local devcontainer database only. Neon facts come from docs/session-log.md. "Local" means the local devcontainer database.

## A. Current web app (apps/web)

1. **Versions.** Next.js 16.4.6, React 19.3.1, TypeScript 5.9.3, ESLint 10 with eslint-config-next. Package manager: npm (package-lock.json). No Tailwind. No UI libraries: no shadcn/ui, Motion, React Flow, icon set or chart library. Diagrams and marks are hand-written inline SVG (app/_ui/flow.tsx, app/_ui/marks.tsx). Font: Archivo via next/font/google.
2. **Layout.** `app/` (routes, `_ui/` shared components, `globals.css` of about 1,840 lines, `layout.tsx` with header, nav and the replay mode banner), `lib/` (api.ts typed API client, replay.ts pure watch helpers, flags.ts, format.ts, errors.ts). Routes:
   - `/` landing: hero plus a preview of the first 9 steps of one featured run (`_ui/preview.tsx`).
   - `/watch` gallery of recorded runs with SVG money-flow cards, filters by pattern and outcome.
   - `/watch/[runId]` step by step replay (`replay.tsx`, client component) with an evidence board; `?step=N` opens at a step.
   - `/queue` approval queue (waiting, decided, all tabs). `/queue/[runId]` full case page (findings, claims, cited transfers, checks, model calls, reviewer, audit trail, decision form).
   - `/evals` eval runs with expandable score blocks. `/lessons` saved reviewer lessons. `/about` how it works (static text). `/corrections` redirects to `/lessons`.
3. **Watch data.** Server-side fetch only: server components call `lib/api.ts`, which fetches `API_BASE_URL` with `cache: "no-store"` and a 20 s timeout. The browser never calls Render. Endpoints: `GET /showcase?limit=200` (gallery; the landing uses limit 60) and `GET /runs/{id}/steps`. The client `Replay` component gets the whole `RunSteps` object as a prop. Types are in `lib/api.ts` (`ShowcaseItem`, `RunSteps`, `ReplayStep`, `FlowGraph`). Trimmed sample:
   ```json
   {"run_id": "e75bcdb8-...", "case_id": "AL-0679023ed0bc", "status": "human_review",
    "recommendation": "close", "confidence": 0.15, "review_verdict": "failed", "tool_steps": 6,
    "alert": {"detector": "fan-out", "summary": "Account 7675/8093BA230 sent to 8 different accounts ...",
              "txn_count": 8, "account_count": 9},
    "teaser": "6 tool calls, then sent to a person: the reviewer agent did not finish its review."}
   ```
   A step: `{"index": 1, "kind": "tool_call", "actor": "agent", "title": "Read the alert", "explanation": "...", "tool": "get_alert", "arguments": {...}, "raw": "...", "claims": [], "txn_ids": []}`. Graph edge: `{"source": "7675/8093BA230", "target": "3698/808222DA0", "count": 1, "txn_ids": [15076], "step": 0}`; nodes carry role (anchor, alert, found), x, y and step.
4. **Design tokens.** Yes, as CSS variables in `app/globals.css` `:root` (paper, ink, intaglio, rule, signal, signal-text, brick, steel, type scale, radii, prose width). No Tailwind config. One font, Archivo with the width axis. Dark mode: yes, automatic via `prefers-color-scheme`, no toggle.
5. **Static or dynamic** (read from code, not from a build). Every page that calls the API is dynamic, because fetches use `no-store`: `/`, `/watch`, `/watch/[runId]`, `/queue`, `/queue/[runId]`, `/evals`, `/lessons`. `/about` sets `force-dynamic` (the layout reads an env flag). `/corrections` is a redirect. Env vars: `API_BASE_URL`, `WEB_DECISIONS_ENABLED`, `REVIEWER_TOKEN`.
6. **Write path.** One server action, `submitDecision` in `app/queue/[runId]/actions.ts`, posting to `POST /runs/{id}/decision` with `REVIEWER_TOKEN` from the server env. Disabled twice on the public deploy: the web refuses unless `WEB_DECISIONS_ENABLED` is "1", and the Render API answers 403 without `REVIEWER_TOKEN` and `REVIEWER_NAME` (docs/deploy.md and render.yaml say never set them there). Whether they are absent is a dashboard fact.

## B. Recorded runs

7. **run_traces** (migration 0006): `run_id` (primary key, foreign key to agent_runs), `trace` jsonb, `case_card` jsonb (the alert as the agent first read it), `created_at`. Append-only by trigger. `trace` is a StoredTrace: `format`, `tool_result_cap` (12,000 chars), `maker` and `checker` (null if no reviewer), each a RunTrace with `messages` (user and assistant; blocks text, tool_call, tool_result), `model_calls`, `tool_calls` (name, arguments, ok, error code, duration, size, truncated), `tool_results` (capped text), `retry_used`, `retry_reason`, `seen_txn_ids`, `lesson_ids`, `error_class`, `trace_id`. Verifier results, findings and final status are NOT in the trace: they are in `agent_runs`; reviewer verdict in `agent_reviews`; human decisions in `case_events`. `/runs/{id}/steps` merges these into step kinds alert, thinking, tool_call, tool_result, retry, checks, review, outcome (no human approval step). Size, local: trace text about 68 KB on average, 163 KB max (about 16 KB and 29 KB stored compressed); about 16 messages and 8 tool calls per run; case card about 7 KB. Steps response median 50 KB (18 steps, 12 nodes, 11 edges), max 90 KB (30 steps, 45 nodes, 46 edges). `/showcase` with 152 items is about 430 KB.
8. **How many.** Local: 152 agent runs in 11 eval runs, all 152 with traces. 20 are fake-model runs (scripted profile: eval runs 20261116T003745Z-6c6bc5 and 20261118T022209Z-a46fb4). 132 are real runs on the free OpenRouter model `nvidia/nemotron-3-ultra-550b-a55b:free` (prompts v1 to v5); reviewers in three runs used Gemma 4 31B free and Ling 3.2 Flash free. Neon: the 9 real runs of prompt v1, v2 and v3 (eval runs 20261116T014628Z-c9d334, 20261116T020950Z-beb465, 20261118T012833Z-e70e00, 3 cases each), at migration 0005, so no traces there yet. Per model call: tokens (in, out, cache read, cache write), cost, latency, stop reason and request id are in `model_calls` (1,242 rows local). Cost is 0 USD for every real run (free models).
9. **Citations.** Findings hold claims and figures, each with `txn_ids` (and amounts with currency and side). Account ids are not cited directly; they follow from the cited transfers. Verifier results are per verifier (citations, arithmetic, alert_membership: passed plus error strings naming the claim or figure), not a structured pass or fail per citation. `/runs/{id}` adds `cited_transfers`, `missing_txn_ids` and `not_fetched_txn_ids`, worked out at request time.
10. **Human approval.** Yes, as `case_events` rows (event approved, rejected or edited, with actor, time, note, hash chain), shown as `decision` in `/runs/{id}` and `/queue`. Local has 0 decisions (only proposal_created 113 and human_review_created 39). Neon most likely has none either; check with a read-only query if it matters.
11. **Anything not public?** Local scan of all 152 traces: no keys, no database URLs, no http URLs, no label fields. The system prompt is not stored (it is sent as the system parameter; the first user message is a one-line case message); only prompt version and sha256 are shown. The tools refuse the `transaction_labels` table, so answer-key labels cannot enter a trace. The trace does hold a Langfuse trace id (an id, not a secret). Words like "laundering" appear only in the model's own reasoning. Care point: labelling a public case "clean catch" or "miss" reveals the truth for that alert; fine for dev alerts (all picks below are dev), not for held-out alerts.
12. **0006 and backfill.** 0006 adds the append-only `run_traces` table; new recorded runs write a trace row and a `trace_digest` in the case event. `evals.backfill_traces` reads each `evals/runs/*/results.jsonl`, matches each case to its recorded agent run (same case, status, reason and findings) and inserts a missing trace row; no model calls, no case events, existing digests untouched. Safe to rerun: rows already stored are counted and skipped, one transaction per run directory, remote targets refused without `--allow-remote`. It needs the local `evals/runs` folders (gitignored), which exist in this Codespace.

## D. Graph data

15. Two existing sources. (a) The replay graph from `/runs/{id}/steps`: accounts and edges seen in the run, but edges carry only count and txn_ids, no time or amount; the full transfer records (time, amount paid and received, currency, format) are in the case card and in tool results inside the trace. (b) Alerts in the database: `alerts` plus `alert_transactions` joined to `transactions` (ts, from and to account, amount and currency both sides, format). Alert size, local, 171 alerts: median 40 transfers, min 2, max 580. `get_transaction_graph` (tools/aml) returns a neighbourhood of one account (1 or 2 hops), capped at 40 nodes and 120 edges, edges as full transfer records, with totals and a truncated flag; but it is an MCP tool for the agent, not an API endpoint. A full alert subgraph for the UI would need a new read-only API endpoint, or reuse of the case card (capped at 12,000 chars, so large alerts are trimmed).

## E. Deploy and CI

16. **Vercel.** Root Directory `apps/web` (docs/deploy.md). Build command: default `next build` (no vercel.json). Node version: not pinned in the repo (no engines field, no .nvmrc); CI uses Node 26; check the dashboard. 18. **Render calls:** `GET /queue`, `/runs/{id}`, `/runs/{id}/steps`, `/showcase`, `/evals`, `/evals/{id}`, `/corrections`, and `POST /runs/{id}/decision` (only when decisions are enabled).
